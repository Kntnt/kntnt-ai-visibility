Read when cutting a release.

Cut releases with Kntnt's `/release` Skill ([ADR-0013](../docs/adr/0013-release-skill-cuts-releases-build-only-builds.md)). It promotes `[Unreleased]` in `CHANGELOG.md`, bumps the `Version:` header in `kntnt-ai-visibility.php`, commits and pushes, tags the commit `vX.Y.Z`, empties `release-assets/` and runs `bin/build-release-assets`, then pushes the tag and creates the GitHub release with the `## [X.Y.Z]` changelog section as its notes and `release-assets/kntnt-ai-visibility.zip` attached, in one step. If the build fails, nothing is published. There is no release workflow: pushing a tag builds nothing.

`bin/build-release-assets` (also `composer build`) builds the zip from the committed `HEAD`, fails when a tagged `HEAD`'s header differs from the tag without its `v`, and never publishes. Only its block between `# ─── Plugin-specific ───` and `# ─── End of plugin-specific ───` belongs to this repository; the rest is shared verbatim with Kntnt's other plugins, so change it there first. The keep-list includes `composer.json` and `composer.lock` for the production `vendor/` install, so they must not be `export-ignore` in `.gitattributes`. The asset name `kntnt-ai-visibility.zip` carries no version – it keeps the `latest/download` URL stable and the `Updater` finds it by content type.
